# Confluence Documents — Skill Router

This skill turns Markdown into reviewed, professionally formatted Confluence Cloud pages and keeps them correct over time. It is not a text generator: it defines a document contract, a safe publish protocol and a set of executable quality gates.

Read this file first. Then open **one** discipline guide from the router table and the matching template. Do not improvise a page skeleton.

## Non-Negotiable Formatting Contract

Every document produced with this skill must satisfy these rules, regardless of document type:

1. **Frontmatter drives the page.** `title`, `doc_id`, `version`, `status`, `owner`, `reviewers`, `jira`, `space`, `labels`, `classification`, `updated` are mandatory. `{{meta}}` renders the document control table.
2. **Tables beat bullets.** Three or more parallel facts become a table with a header row and a stable ID first column. Bullet lines stay at or below 35% of prose lines and no section is bullets-only.
3. **Answer first.** Every `##` section opens with one or two sentences stating the conclusion before any table, list or code block.
4. **Numbered, shallow structure.** Six to twelve numbered H2 sections, depth at most H3 for structure, appendices use letters. `{{toc}}` appears when the page has six or more H2 sections.
5. **Status is text plus colour.** Use `{{status:green|Approved}}`, never a bare green cell. The controlled vocabulary is `Draft`, `In Review`, `Approved`, `Deprecated`, `Superseded`.
6. **Traceability is mandatory.** Requirement rows carry a Jira key; every revision names the issue that authorised it; the change log is the last numbered section and matches the frontmatter version.
7. **No fabricated facts.** Never invent Jira keys, URLs, page IDs, metrics, owners or approval dates. Use an explicit placeholder and mark the page `Draft` when the user has not supplied them.
8. **Accessibility is part of done.** Real heading levels, table headers, descriptive link text, alt text on every image, no colour-only meaning, Vietnamese diacritics preserved.
9. **Markdown is the source of truth.** Storage XHTML is generated by `scripts/md2storage.py`; never hand-edit live page storage as the normal workflow.
10. **No silent writes.** Every update has a reviewed diff, a backup, an explicit version message and a post-write verification.

### Step 2 — Author from the template

Copy the template into the working directory (not into `assets/templates/`), then fill it in this order:

1. Frontmatter — real owner, reviewers, Jira key, space and date.
2. Purpose and scope — one paragraph a newcomer can repeat.
3. Requirement or contract rows — IDs first, Jira column populated.
4. Evidence — tables, diagrams, test links, metrics.
5. Risks and open questions — owner and needed-by date; unresolved ones block approval.
6. Change log — one row per version, newest first.

Keep the section order. If a template section does not apply, write one sentence explaining why it is not applicable; do not delete the heading silently.

### Step 3 — Lint before converting

```bash
python3 scripts/validate_document.py path/to/doc.md \
  --profile fds --min-score 90 --publish
```

Use `--profile fds-vi` for Vietnamese FDS pages. Fix every error; warnings are reviewed, not ignored. The linter checks the formatting contract, not factual correctness — a 100 score does not mean the content is true.

### Step 4 — Convert and inspect

```bash
python3 scripts/md2storage.py path/to/doc.md \
  -o .work/doc.storage.html --manifest .work/doc.json --check
```

`--check` fails on malformed XHTML. Read the manifest to confirm title, space, labels and version before publishing.

### Step 5 — Publish safely

Never create or update from memory. The protocol is:

```bash
# Existing page: read the live storage immediately before editing.
python3 scripts/confluence.py get --page-id 12345 --out .work/current.storage.html

# Preview the exact storage diff.
python3 scripts/confluence.py diff --page-id 12345 --from-md path/to/doc.md

# Update with a human-readable version message. A backup is written automatically.
python3 scripts/confluence.py update --page-id 12345 --from-md path/to/doc.md \
  --message "v1.1 — BR-004: dual approval at 50,000,000 VND" --update-labels

# Prove the remote page matches the source.
python3 scripts/confluence.py verify --page-id 12345 --file .work/doc.storage.html
```

For a new page, use `create --from-md ... --space KEY [--parent-id ID] --dry-run`, review the output, then repeat without `--dry-run`. For a known title, `upsert` is idempotent and skips identical content.

### Step 6 — Report the outcome

State the page title, page ID, URL, version, lint score and verification result. If the write did not happen, say so plainly and give the exact command the user can run. Never imply a page was published when only local files were produced.

## Create Protocol

1. Check for an existing page by title (`search --title` or `--cql`) before creating a duplicate.
2. Resolve the space key and parent page; do not guess either.
3. Start from the matching template; keep the frontmatter contract.
4. Validate with `--publish`; placeholders such as `{Owner}` are errors in publish mode.
5. Dry-run `create`; review title, space, parent and payload size.
6. Create, then verify and report the page ID and URL.
7. Add Jira remote links with `jira-link add` when the issue exists.
8. If credentials are absent, deliver the validated Markdown and storage file, and list the exact create command that remains.

## Update Protocol

1. **Read** the live page and store the storage snapshot in `.confluence-backups/` or `.work/`.
2. **Locate** the smallest anchored section or table row that must change.
3. **Edit** the Markdown source; do not regenerate unrelated sections.
4. **Lint** with the matching profile and `--publish`.
5. **Diff** the generated storage against the live page.
6. **Bump** the version according to the scheme: major for scope, minor for content, patch for typos.
7. **Write** with `--message "v{n} — {area}: {change}"`; never use "update".
8. **Verify** the remote hash and version; if a 409 conflict occurs, stop, re-read and rebase.
9. **Record** the change-log row, the `updated` date and the Jira key.
10. **Reset** an approved page to `In Review` when scope, risk or API behaviour changed.

## No-Credential Fallback

When `CONFLUENCE_BASE_URL`, `CONFLUENCE_EMAIL` and `CONFLUENCE_API_TOKEN` are missing:

- Continue the full authoring, linting and conversion workflow; it needs no network.
- Run `python3 scripts/confluence.py whoami` to confirm the missing configuration and show the error to the user.
- Do **not** ask the user to paste an API token into the chat. Point them to `.env.example` and the Atlassian API-token page.
- Do **not** invent a page ID, URL or publish confirmation.
- Deliver: the Markdown source, the generated `.storage.html`, the lint score, and the exact commands to create or update once credentials exist.

Credentials are read from environment variables or a local `.env`; never commit them and never echo them in output.

## Safety Rules

- **Read before write.** A stale local copy is not a source of truth.
- **Back up.** `update` and `upsert` write a timestamped backup before changing a page.
- **One logical change per version.** Do not mix a restructure with a scope change.
- **Stop on conflict.** A 409 means a human edited the page; re-read and rebase, never retry blindly.
- **Deprecate, never delete.** Old pages keep history and link to the successor.
- **Least privilege.** Use a token with access only to the target spaces.
- **No secrets in documents.** Remove tokens, customer data and internal URLs that should not be public.
- **Respect the tenant.** Confirm installed macros (Mermaid, PlantUML, Jira) before relying on them; fall back to tables and links.

## Commands

| Task | Command |
|---|---|
| Verify identity | `python3 scripts/confluence.py whoami` |
| Fetch a page | `python3 scripts/confluence.py get --page-id ID --out FILE` |
| Search pages | `python3 scripts/confluence.py search --cql '...' --limit 20` |
| List spaces | `python3 scripts/confluence.py spaces --keys PAY,ARCH` |
| List children | `python3 scripts/confluence.py children --page-id ID` |
| List versions | `python3 scripts/confluence.py versions --page-id ID` |
| Diff | `python3 scripts/confluence.py diff --page-id ID --from-md FILE` |
| Create | `python3 scripts/confluence.py create --from-md FILE --space KEY --parent-id ID --dry-run` |
| Update | `python3 scripts/confluence.py update --page-id ID --from-md FILE --message "v1.1 — ..."` |
| Upsert | `python3 scripts/confluence.py upsert --from-md FILE --space KEY --message "v1.1 — ..."` |
| Labels | `python3 scripts/confluence.py labels --page-id ID --add fds,approved --remove draft` |
| Attach | `python3 scripts/confluence.py attach --page-id ID --file IMAGE` |
| Jira link | `python3 scripts/confluence.py jira-link add --page-id ID --issue KEY --title "KEY — summary"` |
| Verify | `python3 scripts/confluence.py verify --page-id ID [--file FILE]` |
| Lint | `python3 scripts/validate_document.py FILE --profile PROFILE --min-score 90 --publish` |
| Convert | `python3 scripts/md2storage.py FILE -o OUT --manifest OUT.json --check` |

All commands accept `--env-file path/to/.env` before the subcommand when credentials live in a file.

## Quality Gates

A document is ready to publish only when all of the following are true:

- [ ] `validate_document.py` passes at the profile's minimum score with `--publish`.
- [ ] `md2storage.py --check` reports a well-formed fragment.
- [ ] The change log matches the frontmatter version and names the Jira issue.
- [ ] Every requirement or contract row has a stable ID and a source.
- [ ] No bullet-only section, no paragraph over 180 words, no unlabelled table.
- [ ] Links are descriptive; images have alt text; status has a text label.
- [ ] The diff contains only the intended change.
- [ ] A backup exists and the post-write verification passed.
